## #36 バケットの公開範囲と、削除までの期間
### 確認した事実（実バケット `gesture-relay-game-assets`）
- 場所: 東京。**均一なアクセス制御 有効**。**公開アクセスの防止: enforced**（外部公開は、できない）。
- アクセスできるのは、プロジェクトのオーナー・エディター・ビューアー、`api-runtime`・`deadline-runtime`（バケット限定の `objectUser`）。
- ライフサイクル: **作成から1日（age: 1）で削除**。
- バージョン管理: なし。保持ポリシー: なし。
- **soft delete（削除後の復元期間）: 7日（604,800秒）。有効。** 削除済みで復元できるファイルが、**実際に残っている**（確認時に4件。現在の通常のファイルは36件）。ライフサイクルが動いて、削除されたことの証拠でもある。
  → 「24時間で自動削除」と説明しているが、実際は、**削除後も最大7日間、管理者が復元できる**。

### 計画
1. ✅ **soft delete を無効にした**（2026-11-09 深夜、マスター承認。`--clear-soft-delete`。変更後の保持期間は 0 秒）。以後に削除されたファイルは、復元できない。
   - すでに削除済みで残っている4件は、保持期間（7日）が過ぎるまで残る。すぐ消したい場合は、別途、完全削除する（承認が要る）。
2. **説明文を正確にする**（README・提出ドキュメント・同意画面の文面）:
   - 現状の文: 「24時間で自動削除」 → 案: 「作成から24時間後に、削除の対象になります（Cloud Storage の仕組みで、実際の削除は、数時間〜1日ほど遅れることがあります）」。
   - soft delete を無効にした後は、「削除後の復元はできません」と書ける。
3. **検証**: 廃棄用のテストデータで、「通常のアクセスが拒否される時点」と「完全削除までの期間」を測る。ライフサイクルは、1日後に動くため、**提出前には、完了しない**。凍結中は、テストデータの作成も控え、**11/14 の終了後に**測定して記録する。
4. アクセス範囲: プロジェクトの「ビューアー」にも、読み取り権限がある（標準の仕組み）。現在の IAM は、オーナー1、エディター（標準アカウント）、firebase.admin・IAM 管理者（フロント担当）、で、ビューアーは見当たらない。**フロント担当に、IAM を変更できる権限（`projectIamAdmin`）があることは、マスターが意図を確認する**（#18・#31 に関わる）。
