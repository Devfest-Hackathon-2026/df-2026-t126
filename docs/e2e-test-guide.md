# 3人の通しテスト（本番）の手順

目的: 本番で、**3人が結果画面まで進めること**を確かめる。審査の「一連の流れが動く」に、直結する。
前提: ①PR #15 が main に取り込み済み ②Hosting を再デプロイ済み（`SKIP_MEDIAPIPE` なしのビルド）③API は版 00005 以降。

## 準備（5分）
- 端末を3つ用意する（スマホ・パソコン）。**人B の端末は、カメラが使えること**。明るい場所で、手を1つ映せること。
- 3人とも、本番の画面の URL を開く（Hosting の URL）。古い画面が残らないよう、再読み込みする。
- 記録係を1人決める（時刻をメモする）。ログの確認は、B（マスター）が行う。

## 手順
1. 1人目: スタート画面 → 名前 → 同意 → 部屋を作る。4桁の参加コードを、2人に伝える。
2. 2人目・3人目: 参加コードで入る。3人で、人A・人B・人C を選ぶ。
3. ホスト: 「ゲームを始める」。**開始した時刻をメモ**。お題の絵が出るまで、数十秒かかる。
4. 人A: 絵を見て、文章にする。
5. 人B: 15秒の準備のあと、8秒、ジェスチャーをする（エフェクトを選ぶ）。
6. 人C: 録画を見て、文章にする。
7. 全員: 結果画面で、「お題・AI の答え・近さ」が出るか確かめる。**結果画面が出た時刻をメモ**。
8. 結果画面で「ロビーへ戻る」を押し、全員が戻れるか確かめる。

## 追加で確かめること（時間があれば）
- ロビーで、1人が「部屋を出る」を押す → 最初の画面に戻れる／ホストが交代する。
- 人B の録画中に、ページを再読み込みする → 続きから送れる。
- 2回目のゲームを、同じ部屋で始められる。

## 結果の見方（B が行う）
```bash
cd ~/Developer/gesture-relay-game && ~/.venvs/gesture-relay-game/bin/python -W ignore scripts/check_run.py 20
```
| 見るところ | 合格の目安 |
|---|---|
| 503 の件数 | 0〜数件（全体の1〜2%以下） |
| 生存確認・ゲーム開始の速さ | 平均 1 秒前後。最大でも 10 秒以内 |
| 部屋の結果 | ✅ finished（結果画面まで進めた） |
| Worker の AI の仕事 | 失敗が多い場合は、原因ログ（`AI API error`）を読む |

AI の失敗の原因は、次のコマンドで読む（Worker の警告ログ）。

```bash
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="worker" AND severity>=WARNING' --limit 20 --format='value(timestamp,textPayload)'
```

## うまくいかなかったとき
- 途中で止まった: 画面の表示と、止まった時刻を、B に伝える（ログを時刻で探せる）。
- 「参加者が退出しました」: 生存確認が止まった可能性。再読み込みをした人、端末をスリープした人がいないか確認。
- 結果画面が出ない: AI の仕事の失敗かもしれない。B が Worker のログを見る。
